# Notion正本の予約システム設定

このシステムでは、Notionの「予約履歴」カレンダーを**予約情報の正本**として扱います。顧客向けの予約フォームはNotionの予約・予定を読んで空き枠を表示し、送信された予約は「予約リクエスト」として同じカレンダーに登録されます。スタッフ用画面では、Notionカレンダーを週表示し、予約状態とスタッフメモを更新できます。

## Notion側の準備

Notionの内部インテグレーションを作成し、対象データベースに対する**読み取り・コンテンツ挿入・コンテンツ更新**の権限を有効にしてください。次に、以下の2つのデータベースを当該インテグレーションへ共有します。Notionは、共有されていないデータソースに対する取得・更新を許可しません。[1] [2]

| データソース | 用途 | 必須プロパティ |
|---|---|---|
| 予約履歴 | 顧客予約、予約状態、スタッフメモ | `Name`、`予約日時`、`サービス種別`、`予約メモ`、`予約状態`、`スタッフメモ` |
| 予定 | スタッフの休業・外出などの予約不可枠 | `予定名`、`終了日時` |

「予約履歴」には、実装により `予約状態`（予約リクエスト／確定／キャンセル／完了）と `スタッフメモ` を追加済みです。既存のNotion予定について `予約状態` が未設定の場合、システムは予約済みとして扱います。

## 環境変数

`.env.example` を参照し、配備先のシークレット設定へ次の値を追加してください。`NOTION_TOKEN` には、Notion内部インテグレーションのシークレットを入力します。トークンをGitHubへコミットしたり、顧客用ブラウザへ渡したりしないでください。

```bash
NOTION_TOKEN=<Notion内部インテグレーションのシークレット>
NOTION_RESERVATION_DATA_SOURCE_ID=2c7fc32c-8e8e-8168-b217-000bd01e5ca4
NOTION_SCHEDULE_DATA_SOURCE_ID=6d510b2b-4128-4b34-9d2f-7e93afffb267
```

## データベース移行

Web予約とNotionページを対応付けるため、生成済みの移行ファイルを本番データベースへ反映してください。

```bash
pnpm db:push
```

この移行では `reservations` テーブルへ `notionPageId` と `notionPageUrl` を追加します。既存予約はNotionページIDを持たないため、スタッフが必要に応じてNotion上で管理してください。新規のWeb予約は作成時からNotionページと接続されます。

## 予約ルール

| ルール | 設定 |
|---|---|
| 営業時間 | 10:00〜21:00 |
| 受付間隔 | 30分 |
| 新規予約枠 | 90分 |
| 休業日 | 日曜・日本の祝日 |
| 予約不可 | Notion「予約履歴」の未キャンセル予約、およびNotion「予定」の重複時間帯 |

顧客画面で選択した枠は、Notionへ登録する直前にもう一度重複検証します。これにより、表示後に他の予定が追加された場合も、重複登録を防ぎます。

## 運用画面

| URL | 利用者 | 用途 |
|---|---|---|
| `/reservation` | 顧客 | Notionカレンダーの空き枠を確認して予約を送信 |
| `/reservations` | スタッフ | Notionカレンダーの週表示、予約状態・スタッフメモの更新、Notionへの直接移動 |

## 検証手順

1. シークレットを投入してサーバーを再起動します。
2. `/reservation` で、Notionに登録済みの予定と重なる90分枠が選べないことを確認します。
3. 空いている枠を送信し、Notion「予約履歴」に氏名、日時、サービス種別、予約メモ、`予約リクエスト` が作成されることを確認します。
4. `/reservations` で予約を開き、状態とスタッフメモを保存して、Notion側にも反映されることを確認します。
